# Структура базы знаний

Все знания находятся в `data/knowledge.json`. При изменении файла перезапустите сервер. Идентификаторы вопросов и правил уникальны.

В `categories` находятся основные жалобы. В `questions` — понятный пользователю вопрос, варианты ответа, подсказка и приоритет. `gate` ограничивает вопрос выбранным путём: например, вопрос о щелчке стартера появляется только при ответе `starter = none`.

Правило содержит `id`, `category`, `type`, `if`, `then` и текст `text` для отчёта и интерфейса. Конструкция `all` означает И, `any` — ИЛИ. Лист условия `{"field":"manual","eq":true}` сравнивает известный ответ с указанным значением. `null` означает неизвестность и не совпадает ни с `true`, ни с `false`.

Пример промежуточного правила:

```json
{"id":2,"category":"start","type":"routing",
 "if":{"all":[{"field":"start_branch","eq":true},{"field":"starter","eq":"none"}]},
 "then":{"fact":"no_rotation"},
 "text":"ЕСЛИ стартер не вращает двигатель, ТО перейти к проверке признаков недостаточного питания."}
```

Пример конечного правила:

```json
{"id":3,"category":"start","type":"terminal",
 "if":{"all":[{"field":"no_rotation","eq":true},{"field":"dashboard_off","eq":true}]},
 "then":{"conclusion":"Возможна разрядка аккумулятора или плохой контакт его клемм","component":"Аккумулятор и клеммы"},
 "text":"ЕСЛИ стартер не вращается И при попытке запуска приборная панель гаснет, ТО возможна разрядка аккумулятора или плохой контакт его клемм."}
```

`constraints` описывает известные логические противоречия между ответами. Это не дополнительная диагностика: если ограничение срабатывает, API возвращает ошибку и просит уточнить сведения. Проверки охватывают только явно перечисленные случаи.

Для нового правила добавьте нужные вопросы, затем правило. Соблюдайте категорию, ссылки на существующие вопросы и промежуточные факты. Не используйте цикл промежуточных фактов: загрузчик отклонит его. Добавьте контрольный пример и выполните тесты.

Порядок вопросов определяется `priority`; при равном приоритете предпочтение получает вопрос, упоминаемый в большем числе оставшихся правил. Приоритеты задаются вручную: алгоритм не рассчитывает энтропию или вероятность неисправности. Завершение опроса происходит, когда больше нет доступных неотвеченных вопросов для не исключённых правил.
